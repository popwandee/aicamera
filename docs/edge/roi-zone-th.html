1 · ROI Zone คืออะไร

ROI Zone (Region of Interest) คือกรอบสี่เหลี่ยมที่กำหนดบนภาพกล้อง โดยใช้พิกัด normalised (0.0 – 1.0) เพื่อกำหนดว่าป้ายทะเบียนที่ตรวจพบในบริเวณใด ควรถูกส่งเข้าสู่กระบวนการ OCR และบันทึกลงฐานข้อมูล

เมื่อ ROI ถูก เปิดใช้งาน ระบบจะส่งเฉพาะป้ายทะเบียนที่มี จุดศูนย์กลาง ของกรอบอยู่ภายในพื้นที่ที่กำหนดไปยัง OCR เท่านั้น ป้ายที่อยู่นอกพื้นที่จะถูกข้ามโดยไม่มีการ OCR และไม่บันทึกลงฐานข้อมูล (ยังคง track รถอยู่ แต่ไม่สร้าง record)

เมื่อ ROI ถูก ปิดใช้งาน (ค่าเริ่มต้น) ป้ายทะเบียนทุกใบที่ตรวจพบ จะผ่านเข้า OCR ทั้งหมด เทียบเท่ากับการกำหนด ROI เต็มภาพ (0,0) → (1,1)

ภาพจากกล้อง (พิกัด normalised)
✅ ROI เปิดใช้งาน
เฉพาะป้ายทะเบียนที่จุดศูนย์กลางอยู่ในกรอบสีน้ำเงินเท่านั้นที่ถูก OCR และบันทึกลงฐานข้อมูล เหมาะสำหรับกล้องที่มองข้ามถนนหลายเลน และต้องการจับเฉพาะเลนที่กำหนด
⬜ ROI ปิดใช้งาน (ค่าเริ่มต้น)
ป้ายทะเบียนทุกใบที่ตรวจพบจะผ่านเข้า OCR โดยไม่มีเงื่อนไขตำแหน่ง เหมาะสำหรับกล้องที่ต้องการเก็บทุกคัน

2 · หลักการทำงานใน Pipeline

ตำแหน่งของ ROI Gate ใน Detection Pipeline

การกรอง ROI เกิดขึ้นภายใน OCR Gate (_should_submit_for_ocr()) หลังจากการ tracking ยานพาหนะและ การตรวจสอบคุณภาพภาพ แต่ก่อนที่ crop ป้ายทะเบียนจะถูกส่งเข้า OCR queue

[ภาพจากกล้อง @30 fps] ↓ [Hailo: ตรวจจับยานพาหนะ] confidence ≥ 0.8 ↓ [Hailo: ตรวจจับป้ายทะเบียน] ↓ [Vehicle Tracking / IoU] กำหนด track_id ↓ [Quality Gate] ตรวจสอบความเบลอ / ขนาด / อัตราส่วน ↓ [ROI Gate] ←─────────────────────────── จุดนี้ จุดศูนย์กลางป้ายอยู่ในโซน? ใช่ → [OCR Queue] → Tesseract/Hailo OCR → DB จุดศูนย์กลางป้ายอยู่นอกโซน? ไม่ใช่ → ข้าม (log [OCR_GATE] SKIP)

ระบบพิกัด

พิกัด ROI ทั้งหมดเป็นค่า normalised ในช่วง [0.0, 1.0] สัมพัทธ์กับขนาดของ frame ดังนั้นพื้นที่จึงปรับขนาดอัตโนมัติตามความละเอียด

จุดความหมายตัวอย่าง
x1, y1มุมบนซ้ายของ ROI0.15, 0.25
x2, y2มุมล่างขวาของ ROI0.85, 0.75
(0, 0)มุมบนซ้ายของภาพ—
(1, 1)มุมล่างขวาของภาพ—

เงื่อนไขที่ต้องปฏิบัติตาม: 0 ≤ x1 < x2 ≤ 1 และ 0 ≤ y1 < y2 ≤ 1

3 · คู่มือใช้งาน — Canvas Editor บน Dashboard

เปิด Dashboard ของกล้องที่ http://<camera>/camera/dashboard
Canvas ROI จะทับอยู่บนภาพ video feed ทางด้านขวาของหน้าจอ

ปุ่มควบคุม

ปุ่มการทำงาน
Edit ROI เข้าสู่โหมดวาด (cursor เปลี่ยนเป็น crosshair) คลิกแล้วลากบน video เพื่อวาดกรอบสี่เหลี่ยมใหม่
Enable / Disable เปิด/ปิดการกรอง ROI โดยไม่เปลี่ยนกรอบที่วาดไว้
Save ROI ส่งกรอบปัจจุบันไปยัง POST /detection/roi ถ้าติ๊ก checkbox Persist ไว้ ค่าจะถูกบันทึกลง .env.production และยังคงอยู่หลัง restart service
Clear / Reset คืนกรอบให้เป็นค่าเริ่มต้น (0.1, 0.2) → (0.9, 0.8) และปิด ROI

การวาดและแก้ไขกรอบ

  1. คลิก "Edit ROI" — badge บนวิดีโอจะเปลี่ยนเป็นสีน้ำเงิน แสดงข้อความ Editing
  2. ลากบน video — วาดพื้นที่ที่ต้องการ ปล่อยเมาส์เมื่อเสร็จ
  3. ปรับละเอียด — ลาก handle มุมสีน้ำเงิน 4 จุดเพื่อปรับขนาด หรือลากตรงกลางกรอบเพื่อย้ายตำแหน่ง
  4. คลิก "Save ROI" — badge เปลี่ยนเป็นสีเขียว แสดงว่า Enabled และพิกัดที่ normalised แล้วจะปรากฏในแผงด้านข้าง

สีของ Badge สถานะ

สีข้อความความหมาย
Disabled ปิดใช้งาน ROI ปิดอยู่ — ป้ายทะเบียนทุกใบผ่านเข้า OCR
Enabled เปิดใช้งาน ROI กำลังกรองอยู่ — เฉพาะป้ายในโซนเท่านั้นที่ถูก OCR
Editing กำลังแก้ไข โหมดวาด/ปรับขนาดกำลังทำงาน

แผงแสดงพิกัด (Side Panel)

ขณะแก้ไข การ์ด ROI ในแผงด้านข้างจะแสดงค่าพิกัด x1, y1, x2, y2 แบบ real-time ก่อนกด Save ค่าเหล่านี้สะท้อนเฉพาะสถานะบน canvas เท่านั้น ยังไม่ได้ส่งไปยัง backend

4 · REST API Reference

GET /detection/roi

คืนค่าการตั้งค่า ROI zone ปัจจุบัน

curl http://<camera>/detection/roi

Response 200:

{
  "success": true,
  "roi": {
    "enabled": false,
    "x1": 0.1,  "y1": 0.2,
    "x2": 0.9,  "y2": 0.8
  },
  "timestamp": "2026-06-09T20:12:42.473198"
}

POST /detection/roi

อัพเดท ROI zone แบบ runtime — มีผลทันทีโดยไม่ต้อง restart service

Request body (JSON):

Fieldชนิดจำเป็นคำอธิบาย
enabledbooleanใช่true เพื่อเปิดการกรอง
x1floatใช่ขอบซ้าย (0.0 – 1.0)
y1floatใช่ขอบบน (0.0 – 1.0)
x2floatใช่ขอบขวา (0.0 – 1.0) ต้องมากกว่า x1
y2floatใช่ขอบล่าง (0.0 – 1.0) ต้องมากกว่า y1
persistbooleanไม่ (default: false) ถ้า true จะบันทึกค่าลง .env.production เพื่อให้คงอยู่หลัง restart

ตัวอย่าง — เปิด ROI เฉพาะช่องทางกลาง:

curl -X POST http://<camera>/detection/roi \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "x1": 0.15, "y1": 0.25,
    "x2": 0.85, "y2": 0.75,
    "persist": true
  }'

Response 200 (สำเร็จ):

{
  "success": true,
  "applied": true,
  "persisted": true,
  "roi": { "enabled": true, "x1": 0.15, "y1": 0.25, "x2": 0.85, "y2": 0.75 },
  "timestamp": "2026-06-09T20:13:39.670518"
}

Response 400 (พิกัดไม่ถูกต้อง):

{
  "success": false,
  "error": "Coordinates must satisfy 0 ≤ x1 < x2 ≤ 1 and 0 ≤ y1 < y2 ≤ 1"
}

ปิด ROI และรีเซ็ตค่าเริ่มต้น

curl -X POST http://<camera>/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled": false, "x1": 0.1, "y1": 0.2, "x2": 0.9, "y2": 0.8, "persist": true}'

5 · การตั้งค่าและการบันทึกถาวร

Environment Variables (edge/installation/.env.production)

ตัวแปรค่าเริ่มต้นคำอธิบาย
ROI_ENABLEDfalseเปิด ROI ตั้งแต่เริ่ม service
ROI_X10.1ขอบซ้าย
ROI_Y10.2ขอบบน
ROI_X20.9ขอบขวา
ROI_Y20.8ขอบล่าง
ℹ️ Runtime vs บันทึกถาวร การเรียก POST /detection/roi โดยไม่ใส่ "persist": true จะอัพเดทเฉพาะใน memory เท่านั้น มีผลทันที แต่จะหายไปเมื่อ restart service ใช้ "persist": true หรือติ๊ก checkbox Persist ใน UI เพื่อบันทึกลง .env.production

แก้ไขไฟล์โดยตรง

# SSH เข้ากล้อง
ssh camuser@aicamera1

# แก้ไข .env.production
nano /home/camuser/aicamera/edge/installation/.env.production

# เพิ่มหรือแก้ไขบรรทัดเหล่านี้:
ROI_ENABLED=true
ROI_X1=0.15
ROI_Y1=0.25
ROI_X2=0.85
ROI_Y2=0.75

# Restart เพื่อให้มีผล
sudo systemctl restart aicamera_lpr.service

6 · การทดสอบ ROI ใน Pipeline จริง

วิธี A — ทดสอบด้วยโซนแคบ (แนะนำ ต้องการรถจริง)

  1. เปิด log monitor บนกล้อง: 
    ssh camuser@aicamera1
sudo journalctl -u aicamera_lpr -f | grep --line-buffered -E "OCR_GATE|ROI"
  2. ตั้ง ROI แคบมาก (บริเวณกลางภาพ 20% เท่านั้น — รถส่วนใหญ่จะอยู่นอกโซน): 
    curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":true,"x1":0.40,"y1":0.40,"x2":0.60,"y2":0.60}'
    Log ที่คาดหวัง เมื่อรถผ่าน: [OCR_GATE] SKIP track=X: plate center (320,400) outside ROI zone
  3. ขยาย ROI เต็มภาพ — รถคันเดิมควรถูก OCR: 
    curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":true,"x1":0.0,"y1":0.0,"x2":1.0,"y2":1.0}'
    Log ที่คาดหวัง: [OCR_GATE] PASS track=X: frames=N score=0.XXX — submitting for OCR
  4. ตรวจสอบ DB ว่ามี record ถูกบันทึก: 
    sqlite3 /home/camuser/aicamera/edge/db/lpr_data.db \
  "SELECT license_plate, confidence, created_at FROM detection_results ORDER BY created_at DESC LIMIT 5;"
  5. รีเซ็ตค่ากลับ: 
    curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":false,"x1":0.1,"y1":0.2,"x2":0.9,"y2":0.8,"persist":true}'

วิธี B — Smoke Test ด้วย API (ไม่ต้องมีรถ)

# 1. GET ดูค่า ROI ปัจจุบัน
curl http://aicamera1.tail605477.ts.net/detection/roi

# 2. POST พิกัดที่ถูกต้อง (ต้องได้ applied:true)
curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":true,"x1":0.2,"y1":0.3,"x2":0.8,"y2":0.7}'

# 3. POST พิกัดที่ผิด (x1 > x2) — ต้องได้ error 400
curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":true,"x1":0.9,"y1":0.1,"x2":0.1,"y2":0.9}'

# 4. ตรวจสอบว่า [ROI] Zone updated ปรากฏใน log
ssh camuser@aicamera1 "sudo journalctl -u aicamera_lpr --since '1 minute ago' | grep ROI"

7 · Log Tokens และการติดตามผล

Tokenระดับเมื่อไรที่เกิด
[ROI] Zone updated: enabled=… (x1,y1)→(x2,y2) INFO set_roi_zone() ถูกเรียกสำเร็จ (ผ่าน API หรือ startup)
[ROI] Invalid zone … — rejected WARN พิกัดที่ส่งมาไม่ถูกต้อง — โซนเดิมยังคงอยู่
[OCR_GATE] SKIP track=X: plate center (px,py) outside ROI zone INFO ตรวจพบป้ายทะเบียนแต่จุดศูนย์กลางอยู่นอก ROI → ไม่ส่ง OCR
[OCR_GATE] PASS track=X: frames=N score=X.XXX — submitting for OCR INFO ป้ายผ่านทุก gate (quality + ROI) และถูกส่งเข้า OCR queue แล้ว
[OCR_GATE] SKIP track=X: … image too blurry … INFO ถูก reject โดย Quality gate (ไม่ใช่ ROI) — ภาพเบลอหรือ score ต่ำเกินไป

ดู log ที่เกี่ยวกับ ROI และ OCR gate แบบ real-time:

sudo journalctl -u aicamera_lpr -f | grep --line-buffered -E "OCR_GATE|ROI"

8 · การแก้ปัญหาที่พบบ่อย

❓ เปิด ROI แล้วแต่ยังมี detection จากนอกโซน

ตรวจสอบว่าระบบใช้ จุดศูนย์กลาง ของกรอบป้ายทะเบียน (ไม่ใช่มุม) ในการตัดสิน: cx = (x1+x2)/2, cy = (y1+y2)/2 แล้ว normalise ด้วยความกว้าง/สูงของ frame

ดู log token [OCR_GATE] SKIP … plate center (px,py) เพื่อดูพิกัดจริงของจุดศูนย์กลาง แล้วเปรียบเทียบกับโซนที่กำหนด

❓ ROI รีเซ็ตกลับหลัง restart service

โซนถูกอัพเดทใน memory เท่านั้น โดยไม่ได้ใช้ "persist": true ส่ง POST อีกครั้งพร้อม "persist": true หรือติ๊ก checkbox Persist ใน UI ก่อนกด Save ROI

❓ GET /detection/roi คืนค่าเริ่มต้น ทั้งที่เคย set ไปแล้ว

Service อาจ restart หลังจากการ set ครั้งล่าสุดที่ไม่ได้ persist ตรวจสอบไฟล์:

grep ROI /home/camuser/aicamera/edge/installation/.env.production

ถ้า ROI keys หายไปหรือเป็นค่าเก่า ส่ง POST ใหม่พร้อม "persist": true

❓ POST ตอบกลับ 400 Invalid ROI parameters

ตรวจสอบว่า x1 < x2 และ y1 < y2 และทุกค่าอยู่ใน [0.0, 1.0] ข้อผิดพลาดที่พบบ่อยที่สุดคือการสลับ x1/x2 เมื่อวาดจากขวาไปซ้าย

❓ กรอบบน Canvas ไม่ตรงกับพื้นที่ video จริง

Canvas ใช้ ResizeObserver เพื่อปรับขนาดตาม video element ลองปรับขนาด browser window เล็กน้อยเพื่อ trigger การคำนวณใหม่ หรือโหลดหน้า Dashboard ใหม่

9 · หมายเหตุด้านสถาปัตยกรรม

ไฟล์ที่เกี่ยวข้อง

ไฟล์หน้าที่
edge/src/components/detection_processor.py _roi_zone dict, get_roi_zone(), set_roi_zone(), _plate_in_roi(), การตรวจสอบ ROI ใน _should_submit_for_ocr()
edge/src/web/blueprints/detection.py Route GET/POST /detection/roi และการ persist ลง .env.production
edge/src/web/templates/camera/dashboard.html Canvas overlay, drag-to-draw, corner handles, ปุ่ม Save/Clear, แผงแสดงพิกัด
edge/src/core/config.py ROI_ENABLED, ROI_X1/Y1/X2/Y2 — โหลดจาก .env.production

Thread Safety

_roi_zone ถูกแทนที่แบบ atomic ด้วย dict ใหม่ทุกครั้งที่ set_roi_zone() ถูกเรียก Detection loop อ่าน dict reference ภายใต้ Python GIL จึงไม่จำเป็นต้องใช้ explicit lock สำหรับ pattern นี้ (single-writer, single-reader)

การแปลงพิกัดใน _plate_in_roi()

cx = (plate_bbox[0] + plate_bbox[2]) / 2 / frame_width   # x normalised
cy = (plate_bbox[1] + plate_bbox[3]) / 2 / frame_height  # y normalised
return roi['x1'] <= cx <= roi['x2'] and roi['y1'] <= cy <= roi['y2']
