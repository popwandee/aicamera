1 · Overview

The Region of Interest (ROI) zone is a rectangular area, defined in normalised image coordinates (0.0 – 1.0), that gates which detected license plates are submitted for OCR and saved to the database.

When ROI is enabled, only plates whose bounding-box centre falls inside the rectangle pass through to OCR. Plates outside the zone are silently skipped — vehicles are still tracked, but no OCR job is queued and no database record is created.

When ROI is disabled (default), every detected plate is treated as inside the zone and proceeds normally.

camera frame (normalised)
✅ ROI Enabled
Only plates whose centre is inside the blue rectangle are OCR'd and saved. Use this to focus on a specific lane or gate.
⬜ ROI Disabled (default)
All detected plates proceed to OCR regardless of position. Equivalent to a full-frame ROI (0,0) → (1,1).

2 · How It Works

Pipeline position

ROI filtering happens inside the OCR gate (_should_submit_for_ocr()), after vehicle tracking and plate quality checks, but before the plate crop is placed on the async OCR queue.

[Camera Frame @30 fps] ↓ [Hailo: Vehicle Detection] confidence ≥ 0.8 ↓ [Hailo: Plate Detection] ↓ [Vehicle Tracking / IoU] assign track_id ↓ [Quality Gate] blur / size / aspect checks ↓ [ROI Gate] ←─────────────────────────── HERE plate centre inside zone? YES → [OCR Queue] → Tesseract / Hailo OCR → DB plate centre outside zone? NO → SKIP (log [OCR_GATE] SKIP)

Coordinate system

All ROI coordinates are normalised to [0.0, 1.0] relative to the frame dimensions, so the zone scales correctly regardless of resolution.

PointMeaningExample
x1, y1Top-left corner0.15, 0.25
x2, y2Bottom-right corner0.85, 0.75
(0, 0)Top-left of frame—
(1, 1)Bottom-right of frame—

Constraints enforced by the API: 0 ≤ x1 < x2 ≤ 1 and 0 ≤ y1 < y2 ≤ 1.

3 · UI Guide — Dashboard Canvas Editor

Open the camera dashboard at http://<camera>/camera/dashboard. The ROI canvas overlays the live video feed on the right side.

Toolbar buttons

ButtonAction
Edit ROIEnters draw mode (cursor becomes crosshair). Click and drag on the video to draw a new rectangle.
Enable / DisableToggles ROI filtering on/off without changing the drawn rectangle.
Save ROISends the current rectangle to POST /detection/roi. If the Persist checkbox is ticked, the zone is also written to .env.production and survives a service restart.
Clear / ResetRestores the rectangle to the default full-frame zone (0.1, 0.2) → (0.9, 0.8) and disables ROI.

Drawing & editing the rectangle

  1. Click "Edit ROI" — badge turns blue and shows Editing.
  2. Drag on the video — draw the desired zone. Release the mouse button to finish.
  3. Fine-tune — drag any of the four blue corner handles to resize, or drag the rectangle body to move it.
  4. Click "Save ROI" — the badge shows Enabled (green) and the normalised coordinates appear in the side panel.

Status badge

ColourLabelMeaning
DisabledDisabledROI filtering off — all plates pass to OCR.
EnabledEnabledROI active — only plates inside the zone are OCR'd.
EditingEditingDraw/resize mode is active.

Side panel — live coordinates

While editing, the ROI card in the side panel refreshes the four coordinate values in real time. Before saving, these reflect the canvas state only and have not been sent to the backend.

4 · REST API Reference

GET /detection/roi

Returns the current ROI zone configuration.

curl http://<camera>/detection/roi

Response 200:

{
  "success": true,
  "roi": {
    "enabled": false,
    "x1": 0.1,  "y1": 0.2,
    "x2": 0.9,  "y2": 0.8
  },
  "timestamp": "2026-06-09T20:12:42.473198"
}

POST /detection/roi

Updates the ROI zone at runtime. Takes effect immediately — no restart required.

Request body (JSON):

FieldTypeRequiredDescription
enabledbooleanyestrue to activate filtering.
x1floatyesLeft edge (0.0 – 1.0).
y1floatyesTop edge (0.0 – 1.0).
x2floatyesRight edge (0.0 – 1.0), must be > x1.
y2floatyesBottom edge (0.0 – 1.0), must be > y1.
persistbooleanno (default false) If true, writes values to .env.production so the zone survives a service restart.

Example — enable a centre lane ROI:

curl -X POST http://<camera>/detection/roi \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "x1": 0.15, "y1": 0.25,
    "x2": 0.85, "y2": 0.75,
    "persist": true
  }'

Response 200 (success):

{
  "success": true,
  "applied": true,
  "persisted": true,
  "roi": { "enabled": true, "x1": 0.15, "y1": 0.25, "x2": 0.85, "y2": 0.75 },
  "timestamp": "2026-06-09T20:13:39.670518"
}

Response 400 (invalid coords):

{
  "success": false,
  "error": "Coordinates must satisfy 0 ≤ x1 < x2 ≤ 1 and 0 ≤ y1 < y2 ≤ 1"
}

Disable ROI (reset to defaults)

curl -X POST http://<camera>/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled": false, "x1": 0.1, "y1": 0.2, "x2": 0.9, "y2": 0.8, "persist": true}'

5 · Configuration & Persistence

Environment variables (edge/installation/.env.production)

VariableDefaultDescription
ROI_ENABLEDfalseEnable ROI at startup.
ROI_X10.1Left edge.
ROI_Y10.2Top edge.
ROI_X20.9Right edge.
ROI_Y20.8Bottom edge.
ℹ️ Runtime vs Persisted Calling POST /detection/roi without "persist": true updates the zone in memory only. The change takes effect immediately but is lost on the next systemctl restart. Use "persist": true or the Persist checkbox in the UI to write the zone to .env.production.

Manual edit

# SSH into the camera
ssh camuser@aicamera1

# Edit .env.production
nano /home/camuser/aicamera/edge/installation/.env.production

# Add or update:
ROI_ENABLED=true
ROI_X1=0.15
ROI_Y1=0.25
ROI_X2=0.85
ROI_Y2=0.75

# Restart to apply
sudo systemctl restart aicamera_lpr.service

6 · Testing ROI in the Pipeline

Method A — Narrow zone test (recommended, requires live traffic)

  1. Open a log monitor on the camera: 
    ssh camuser@aicamera1
sudo journalctl -u aicamera_lpr -f | grep --line-buffered -E "OCR_GATE|ROI"
  2. Set a narrow ROI (centre 20 % of frame — most vehicles will be outside): 
    curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":true,"x1":0.40,"y1":0.40,"x2":0.60,"y2":0.60}'
    Expected log when a vehicle passes: [OCR_GATE] SKIP track=X: plate center (320,400) outside ROI zone
  3. Expand ROI to full frame — same vehicle should now be OCR'd: 
    curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":true,"x1":0.0,"y1":0.0,"x2":1.0,"y2":1.0}'
    Expected log: [OCR_GATE] PASS track=X: frames=N score=0.XXX — submitting for OCR
  4. Verify DB record created: 
    sqlite3 /home/camuser/aicamera/edge/db/lpr_data.db \
  "SELECT license_plate, confidence, created_at FROM detection_results ORDER BY created_at DESC LIMIT 5;"
  5. Reset to defaults: 
    curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":false,"x1":0.1,"y1":0.2,"x2":0.9,"y2":0.8,"persist":true}'

Method B — API smoke test (no traffic required)

# 1. GET current zone
curl http://aicamera1.tail605477.ts.net/detection/roi

# 2. POST a valid zone (should return applied:true)
curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":true,"x1":0.2,"y1":0.3,"x2":0.8,"y2":0.7}'

# 3. POST invalid zone (x1 > x2) — should return 400
curl -X POST http://aicamera1.tail605477.ts.net/detection/roi \
  -H "Content-Type: application/json" \
  -d '{"enabled":true,"x1":0.9,"y1":0.1,"x2":0.1,"y2":0.9}'

# 4. Verify [ROI] Zone updated in journal
ssh camuser@aicamera1 "sudo journalctl -u aicamera_lpr --since '1 minute ago' | grep ROI"

7 · Log Tokens & Observability

TokenLevelWhen emitted
[ROI] Zone updated: enabled=… (x1,y1)→(x2,y2) INFO set_roi_zone() called successfully via API or startup.
[ROI] Invalid zone … — rejected WARN Bad coordinates passed to set_roi_zone(); previous zone unchanged.
[OCR_GATE] SKIP track=X: plate center (px,py) outside ROI zone INFO Plate detected but its centre is outside the enabled ROI → no OCR.
[OCR_GATE] PASS track=X: frames=N score=X.XXX — submitting for OCR INFO Plate passed all gates (quality + ROI) and was submitted to the OCR queue.
[OCR_GATE] SKIP track=X: … image too blurry … INFO Quality gate rejection (not ROI) — plate too blurry or low score.

Monitor all ROI + OCR gate events:

sudo journalctl -u aicamera_lpr -f | grep --line-buffered -E "OCR_GATE|ROI"

8 · Troubleshooting

❓ ROI is enabled but detections still appear outside the zone

Check that the plate centre (not the bounding-box corner) is inside the zone. The gate uses the midpoint of the plate bbox: cx = (x1+x2)/2, cy = (y1+y2)/2 in pixel space, then normalised to [0,1].

Use the log token [OCR_GATE] SKIP … plate center (px,py) to see the actual centre coordinates and compare against your zone.

❓ ROI resets to defaults after service restart

The zone was updated at runtime without "persist": true. Either re-send the POST with "persist": true, or tick the Persist checkbox in the dashboard UI before clicking Save ROI.

❓ GET /detection/roi returns default values, not what I set

The service may have restarted since the last non-persisted update. Check .env.production:

grep ROI /home/camuser/aicamera/edge/installation/.env.production

If the ROI keys are missing or have old values, send the POST again with "persist": true.

❓ POST returns 400 Invalid ROI parameters

Ensure x1 < x2 and y1 < y2, and all values are in [0.0, 1.0]. The most common mistake is swapping x1/x2 when drawing right-to-left.

❓ Canvas rectangle does not match the actual video area

The canvas is sized to match the video element using a ResizeObserver. Try resizing the browser window slightly to trigger a recalculation, or reload the dashboard page.

9 · Architecture Notes

Thread safety

_roi_zone is replaced atomically with a new dict on every set_roi_zone() call. The detection loop reads the dict reference under Python's GIL — no explicit lock is needed for this single-writer, single-reader pattern.

Coordinate conversion inside _plate_in_roi()

cx = (plate_bbox[0] + plate_bbox[2]) / 2 / frame_width   # normalised x centre
cy = (plate_bbox[1] + plate_bbox[3]) / 2 / frame_height  # normalised y centre
return roi['x1'] <= cx <= roi['x2'] and roi['y1'] <= cy <= roi['y2']
